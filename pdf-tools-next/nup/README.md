# 모아찍기 · 같은 쪽 여러 개 찍기 (`/pdf-tools/nup/`)

PDF를 A4 한 장에 모아 넣는 손님용 도구입니다. 서버 코드가 없는 정적 페이지이고, 파일은 손님 브라우저 안에서만 처리합니다(서버로 보내지 않음).

- **여러 쪽 모아찍기**: 여러 쪽을 A4 한 면에 2쪽 또는 4쪽씩. 원고 방향을 보고 용지 방향을 자동으로 골라 가장 크게 놓습니다(세로 원고 2쪽 → A4 가로, 4쪽 → A4 세로. 가로 원고는 반대). 모든 쪽이 대상입니다.
- **같은 쪽 여러 개 찍기**: 한 쪽을 A4 한 면에 2·4·8개씩 똑같이. 여러 쪽 파일이면 쪽마다 한 면. 자르는 선을 넣을 수 있습니다.
- 옵션: 쪽 놓는 방식(자동/좌우·A4 가로/위아래·A4 세로), 읽는 순서(왼→오, 오→왼), 간격(없음 0 / 좁게 4mm / 넓게 10mm), 테두리 선, 자르는 선. 바깥 여백은 5mm 고정.
- 바로 열기 주소: `?job=nup2`, `?job=nup4`, `?job=repeat2`, `?job=repeat4`, `?job=repeat8` (`#nup4` 형식도 됨).
- 결과 파일명: `원본명_2쪽모아찍기.pdf`, `원본명_4개반복배치.pdf`. 결과에 원본을 첨부하지 않습니다. 받기 링크는 화면을 떠나기 전까지 유지됩니다.

## 파일 구성

| 파일 | 역할 |
|---|---|
| `index.html`, `nup.css` | 화면(디자인 시안 `tool.html`의 토큰·컴포넌트 그대로). 인라인 스크립트·스타일 없음 |
| `js/layout.js` | 배치 계산과 PDF 생성(pdf-lib). 화면 미리보기와 실제 생성이 같은 계산을 씀 |
| `js/worker.js` | PDF 생성을 화면과 분리해 실행(화면이 멈추지 않음, 취소 가능) |
| `js/app.js` | 화면 동작, pdf.js 미리보기, 오류 문구 |
| `vendor/` | pdf-lib 1.17.1, PDF.js 5.4.624(legacy 빌드)와 부속 자료, `vendor/LICENSES/` 고지 |
| `tests/` | 자동 테스트와 스크린샷 |

## 서버에 올리는 방법

1. 이 폴더(`nup/`)를 통째로 웹루트의 `/pdf-tools/nup/`로 복사합니다. `tests/`는 올리지 않아도 됩니다.
2. `https://moducopy.co.kr/pdf-tools/nup/?job=nup2`를 열어 PDF 하나로 만들어 봅니다.
3. 다른 페이지에서 이 주소로 링크를 걸기 전까지는 기존 화면에 아무 영향이 없습니다.

**되돌리는 방법**: 서버에서 `/pdf-tools/nup/` 폴더를 지우고, 걸어 둔 링크가 있으면 뺍니다. 기존 파일은 하나도 건드리지 않습니다.

## 서버 설정 주의

- **`.js` 파일은 `text/javascript`로 전송돼야 합니다.** PDF.js 파일을 `.mjs`가 아닌 `.js`로 실은 이유입니다(구형 Apache는 `.mjs` 형식을 모름).
- **CSP를 쓰는 경우** 아래 정책에서 동작을 확인했습니다(테스트 서버가 이 헤더를 붙입니다).
  ```
  default-src 'none'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self'; img-src 'self' blob: data:;
  worker-src 'self'; connect-src 'self'; font-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'self'
  ```
  `worker-src 'self'`와 `script-src 'self'`가 없으면 미리보기와 만들기가 모두 안 됩니다. `'wasm-unsafe-eval'`은 JPEG2000·JBIG2 이미지가 든 PDF의 미리보기에 필요합니다.
- 상위 폴더 `.htaccess`가 `/pdf-tools/` 전체를 PHP로 돌리거나 접근을 막는 규칙이 있으면 이 폴더가 예외인지 확인하세요(현재 서버 설정은 확인하지 못했습니다).
- 파일을 고쳐 다시 올릴 때는 `index.html`의 `?v=`와 `js/app.js`의 `VERSION` 값을 함께 바꿔야 손님 브라우저가 새 파일을 받습니다.
- 헤더 링크는 `/pdf-tools/start/`, `/pdf-tools/basic/`, `/pdf-tools/converter/`, `/pdf-tools/print/`, `/shop/`입니다. `start/`가 아직 없으면 그 탭은 404가 됩니다.

## 테스트

Node와 Playwright(Chromium)가 필요합니다. 실제 고객 파일은 쓰지 않고 합성 PDF만 씁니다.

```
node tests/run.mjs            # 전체 자동 테스트 (약 3분)
node tests/run.mjs --shots    # + tests/shots/ 에 1280·390 스크린샷
node tests/serve.mjs 8787     # 눈으로 보기: http://127.0.0.1:8787/pdf-tools/nup/
```

테스트는 합성 PDF를 실제 화면에 올리고 ‘PDF 받기’로 받은 파일을 다시 읽어, 면 수·용지 크기·쪽 순서·배율·쪽 위치를 `js/layout.js`와 따로 계산한 기대값과 비교합니다. 결과 그림과 `results.json`은 `tests/out/`에 남습니다.

## 알려진 한계

- **암호가 걸린 PDF는 처리하지 않습니다**(열기 암호, 편집 제한 모두). 안내 문구가 나옵니다.
- **큰 파일**: 파일을 통째로 메모리에 올립니다(대략 파일 크기의 3~4배). 150MB부터 경고, 1GB 초과는 받지 않습니다. 수백 MB 파일과 휴대폰에서의 동작은 실측하지 않았습니다.
- **링크·책갈피·입력 양식 기능은 결과에 남지 않습니다.** 양식에 적힌 값과 도장·메모의 보이는 모양은 쪽에 그려 넣습니다.
- 600쪽을 넘는 파일은 앞 600쪽의 크기로 용지 방향을 정합니다.
- 방향이 섞인 원고의 모아찍기는 문서 전체에 한 가지 용지 방향을 씁니다(쪽마다 돌리지 않음). 작은 원고는 칸에 맞춰 확대됩니다.
- 색상 변환, 재단 여백(도련), 소책자 배치는 없습니다. 용지는 A4만 됩니다.
- 화면 글꼴은 Pretendard 파일을 싣지 않았습니다. 쇼핑몰이 Pretendard를 불러오는 방식(CSS 주소)을 확인하면 `nup.css`에 한 줄 추가하면 됩니다.
- Chromium에서만 자동 테스트했습니다. Safari·Firefox·삼성 인터넷·카카오톡 인앱 브라우저는 확인하지 않았습니다. `:has()`를 쓰므로 2022년 이전 브라우저에서는 선택한 옵션 칸의 강조 표시가 보이지 않을 수 있습니다(동작은 됨).
- 주문 연결은 링크입니다. 파일이 주문서로 자동 전달되지 않으며, 화면에 그렇게 적어 두었습니다.
